================================================================
 单周期 CPU 工程骨架  (MIPS 8 条指令)
================================================================

指令集: add sub and or slt lw sw beq
目标:   熟悉 CPU 前端流程，不上板

这份骨架里 RTL 只有端口和 TODO，逻辑留给你自己写；
测试台、汇编器、Makefile 是完整可用的，省掉重复劳动。


----------------------------------------------------------------

                  关键连线 / 常见坑  <-- 写代码时开着它

Makefile

----------------------------------------------------------------
 环境（Ubuntu）
----------------------------------------------------------------
sudo apt update
sudo apt install -y iverilog gtkwave verilator make python3

iverilog 是 4 态仿真器，能看到 x；verilator 是 2 态但检查更严。
两个都装，分工用，不要只留一个。


----------------------------------------------------------------
 工作顺序（建议）
----------------------------------------------------------------
第 0 步  把整个目录 copy 进虚拟机，cd 进去，确认 make 能跑：
            make help

第 1 步  读 docs/design.txt，把三张表过一遍。有想不通的地方
         先改表，别急着写代码。

第 2 步  自底向上写，每写完一个模块立刻单独验一次，别攒着：
            iverilog -g2012 -Wall -o /tmp/t_alu rtl/alu.v tb/tb_alu.v
            vvp /tmp/t_alu
         建议顺序：
            signext -> alu -> alucontrol -> regfile -> control
            -> imem/dmem -> pc -> datapath -> cpu_top
         除了 alu，其余模块的 mini testbench 照 tb_alu.v 的样子写。

第 3 步  顶层写完，跑 prog1：
            make sim
         看到 *** PASS *** 就说明 8 条指令全对。

第 4 步  换 prog2 再跑一遍，验证循环和负数偏移：
            make sim PROG=prog2

第 5 步  看波形，确认自己真的看懂了数据流：
            make wave


----------------------------------------------------------------
 Makefile 命令
----------------------------------------------------------------
make sim             汇编 + 仿真 + 自检（默认 PROG=prog1）
make sim PROG=prog2  换测试程序，不用改 RTL
make asm             只汇编，不仿真
make wave            跑完直接开 gtkwave
make lint            verilator 静态检查
make clean           清理 build 和生成的 hex

注意：所有命令都要在工程根目录执行，因为 $readmemh 的路径是
      相对当前工作目录的，不是相对 .v 文件。


----------------------------------------------------------------
 这几个名字不能改（tb 靠层次引用读内部信号）
----------------------------------------------------------------
cpu_top  里：    u_datapath / u_control
datapath 里：    u_pc / u_imem / u_regfile / u_dmem / u_alu
regfile  里：    regs [0:31]
imem/dmem 里：   mem  [0:255]

改了 tb_cpu.v 会报找不到层次。信号名（pc_plus4 / alu_result 之类）
随你，只有实例名和上面几个数组名有约束。


----------------------------------------------------------------
 几句提醒
----------------------------------------------------------------
* 先只跑通 add 一条指令，端到端通了再一条一条加。别一次写完
  8 条再调，那样出错时你没法定位是哪一层的问题。

* 波形里信号是 x，十有八九是某根线压根没赋值，不是"逻辑算错了"。
  先查连接，再查运算。

* 汇编器已经帮你把机器码和期望值都算好了。改了 .asm 之后
  make sim 会自动重新汇编，不用手动跑 python。

* 期望终态写在 .asm 末尾的 .expect 行里，改测试程序时顺手改。
  没写的项就不检查，所以可以先只写关心的那几个。
